## 3. 新方案里我建议改 / 确认的 8 处

**① `terms` 和 `params` 靠下标隐含对应，不可靠。**
`terms:[{coef:1,pow:3},{coef:-3,pow:1}]` 与 `params:[a,b]` 谁对应谁，只能靠"都是第一个"。
一旦某次 `terms` 塌掉一个零系数项，滑条就会驱动错的项。
→ **改法**：`terms[i].param = "a"`，显式绑定。已在我的 Swift 结构里按这个思路留了 `pow` 字段，
你在 P2 那边加一个 `param` 就行。

**② `coef` 不要用 Double。**
`0.1 + 0.2 != 0.3` 这类误差会让"判对错"在边界上抖；`\frac{1}{2}x^2` 用 Double 存成 0.5 没事，
但 `\frac{1}{3}` 就会出现 `0.3333333333333333` 和 `0.33333333333333337` 两种。
→ **改法**：用有理数（`n/d`，分子分母都是 Int）。我已经写好 `Rational`，`==` 是精确的。

**③ 批注里删 `expected_latex` 是对的，但 `wrong_latex` 必须带字符区间。**
只有 `bbox` 的话，P1 只能整行圈，圈不到 `-3x` 那一小段。
→ **改法**：加 `char_span: [start, end)`，相对**服务端归一化后的 body**（响应里同时回 `rhs_latex`）。
我已经实现：D01 的 `-3x` 落在 `[4,7)`。

**④ 测试夹具必须留 `expected_latex`。**
线上不返回，不等于测试里不要。没有它，回归测试只能判"错了"，判不了"错成了什么"。
→ `golden_cases.json` 里保留了，只在 XCTest 里用。

**⑤ 解析器要按 MyScript / Flash 的**真实输出**写，不要按想象写。**
我在 Python 版踩过：`f^{\prime}(x)`、`x²`、`3 x^{2}`、全角 `−`、`\left(` 都出现过，
每一种都能让"看起来没问题"的解析器当场返回 parse_error。
→ **改法**：第 0–4 小时让 P3 把 20 张样本的 LaTeX **字符串**（不是截图）发给你，
直接塞进 `golden_cases.json` 的 `parse` 段。`P01–P15` 已经是 15 种脏写法，照着加。

**⑥ 极值只支持导数次数 ≤ 2，要在契约里说清楚。**
`x^4` 这类题目导数三次，我的 `realRoots` 会静默返回空数组 → 图上不标点，看起来像"算对了但没画"。
→ **改法**：超范围时返回 `degraded: ["marks_unsupported"]`，前端显示一行小字而不是静默。

**⑦ 定积分用 Simpson，不要在 Swift 里写符号积分。**
方案只说"不定积分对学生结果求导"。定积分如果也想做，符号积分要写换元/分部，3 小时打不住。
→ **改法**：Simpson 数值（多项式三次以下精确），10 行代码。我已实现。

**⑧ 回放要定义"什么算一次命中"。**
"把每一步的真实响应存起来"没说存哪个 key。
→ **改法**：按 `(endpoint, 请求体 JSON 的规范化哈希)` 存。请求体里只要有时间戳或 UUID 就会永不命中。
我在 Python 版用 `sort_keys` 的 SHA1，实测命中 9 ms，可以直接照抄。

## 7. 关于你给的两个链接

先说明：**这台机器抓不到外部页面**（`github.com`、`developer.myscript.com` 的域名解析被拦），
所以我没法替你逐条核对价格条款和许可文件。下面是我能从方案本身判断的部分，
以及你去页面上要回答的具体问题。

### GeoGebra：方案的处理是对的，别动

- 48 小时内**不克隆、不嵌入、不用 `deployggb.js`** —— 这三条都同意。理由不是许可，是**时间**：
  它是 Java/GWT 的构建链，和 SwiftUI 没有任何可复用的地方。
- 抄走的只有**对象模型**：自由点可拖、依赖点由关系定义、拖动后重算、代数与几何是同一对象的两种视图。
  这四条是**思想**，不是代码，随便用。
- 许可细节（源码是 EUPL 1.2 还是 GPL-3+）我这边查不实（公开资料里有历史争议记录）。但这不影响结论：
  **一行代码都不拷，就不需要谈许可。** 你如果要在路演里提 GeoGebra，就说"借鉴了它的对象模型"，别说"基于 GeoGebra"。
- 另外提醒 P2：**三条中线交于一点不需要求解器**。每条中线都是「顶点 → 对边中点」，而中点是
  `midpoint` 关系算出来的，交点自然会重合。别让他去写约束求解 —— 那是 8 小时的坑。
  我在 `Geometry.resolve` 里已经按这个模型写好，`centroid` 只用于验证。

### MyScript：决策对，但要今天就把"外部等待"清零

- 选它是对的：iink 能在设备上直接出 LaTeX（不给后段传整页图），正好符合新方案的"四段数据流"。
- 但它是**唯一有外部等待时间**的依赖（账号、SDK 获取、key 绑定 bundle id、证书）。
  这种依赖在 48 小时里只有一种处理方式：**第 0 小时就申请，第 4 小时必须有结论**。
- 你去 pricing 页面要回答这 5 个问题（决定它能不能进演示）：
  1. 有没有**免费试用/开发者层**，有效期多长，是否够两天？
  2. key 是**即时签发**还是要人工审核？审核多久？
  3. 是**设备端引擎**还是必须走云？走云就意味着现场断网即死。
  4. 免费层有没有**水印、调用次数上限、或"禁止用于公开演示"**的条款？
  5. 数学识别（不是手写文字识别）是否需要**单独的内容类型/资源包**，那个包要不要额外授权？
- 验收标准不要写成"准确率"，写成一句话：
  **「在真机上把 `f'(x)=3x^2-3x` 转成 LaTeX，端到端 < 800 ms」** ——
  这条过了就用它，不过就切 Flash，**不要在比赛里换第三家**。
