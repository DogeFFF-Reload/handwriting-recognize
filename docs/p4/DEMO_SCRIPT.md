# 演示脚本 · 3 分钟

> P4 的交付物之一。目标不是"讲清楚"，是**让评委在 3 分钟里看到一次"被指到那一项"的惊讶**。
> 结构：惊讶 → 信任 → 想象空间。所有秒数按彩排实测调整，第一次彩排一定超时 40 秒，砍话术不要砍幕。
>
> **2026-10-20 改动（v3）**：反馈改成 `direct` 模式 —— 圈住错项后**直接给出正确项 + 一句说明**，
> 不再只给反问（D5）。题目改成 `x³ − 5x`（第一幕结尾正好接到第二幕的 `x³ − 3x`）。
> 批改由「1.5 秒无新笔画」或「Pencil 双击」触发（D1）。

---

## 0. 时间分配

| 段 | 秒 | 内容 | 目的 |
|---|---|---|---|
| 开场 | 0:00–0:15 | 一句话价值主张 | 让评委知道你要干什么 |
| 幕一 | 0:15–0:55 | 写函数 → 图出现 → 改系数 → 滑块 | **惊讶 1：笔迹直接变成可操作的图** |
| 幕二 | 0:55–1:55 | 写错导数 → 圈出那一项 → 给出正确项和原因 → 改对 → 极值点 | **惊讶 2：它知道错在哪一项** |
| 幕三 | 1:55–2:30 | 手绘三角形 + 中线 → 拖动顶点 | 惊讶 3：纸上草图变成动态几何 |
| 加分 | 2:30–2:45 | 矩阵或积分，10 秒一个 | "同一套引擎"的证据 |
| 收尾 | 2:45–3:00 | 团队 + 一句话 | 记住人 |

**如果只给你 90 秒**：开场 10s + 幕一 25s + 幕二 45s + 收尾 10s。幕二不能砍。

---

## 1. 开场（0:00–0:15）

> **台词**
> "学生写错了，老师要 30 秒才能发现错在哪一项。我们把这个时间压到 1 秒 ——
> 笔一抬，错的**那一项**被圈出来，旁边写着它该是什么，还有一句为什么。"

不要念功能列表。不要先说技术栈（会被问"所以呢"）。

---

## 2. 幕一：函数图像（0:15–0:55）

**手上动作**

1. 左半屏写 `f(x) = x³ − 5x`，写完停住（抬笔后 0.7 秒才识别，**别急着接着写**）。
2. 右半屏出现图像（P50 < 2.5 秒）；系数旁出现 `a`、`b` 两个滑条，`b` 上是 **5**。
3. **用橡皮按钮整笔擦掉 `5`**，再写 `3`（D3：先擦再写，每次整行重识别）。
4. 抬笔 → 图像实时变形为 `x³ − 3x`，`b` 滑条跳到 **3**。双击 Pencil 可以立即刷新图像（不用等 1.5 秒）。
5. 拖动 `b` 滑条给评委看：曲线和极值点跟着动。

**台词（边写边说，不要停）**

> "右边这张图不是我画的，是他写的那一行。"
> "现在我把系数 5 改成 3 —— 图跟着变，滑条也跳过去了。拖动它，曲线和极值点一起动。"
> "这一步没有老师，只有一个笔迹。"

**注意**：写 `x³` 时把指数 3 写小、抬高，别贴着 x；两项之间留 8 mm。
这是彩排要练的"写法约定"，直接决定识别率。**擦除要用整笔擦的橡皮（vector），不要用位图橡皮** ——
后者会把一笔切成几段，笔画 id 就乱了。

## 3. 幕二：求导批改（0:55–1:55）—— 整场核心

**手上动作**

1. 在下一行**故意写错**：`f'(x) = 3x² − 5x`（错在第二项，`−5` 写成了 `−5x`），**一笔连着写完**。
2. 停 1.5 秒（没有新笔画），自动批改；或者双击 Pencil 立即批改。
3. 屏幕上 `−5x` 被笔迹动画圈住（约 0.3 秒），**先圈、后出字**。
4. 圈旁出现：正确项 **−5**（SwiftMath 排版，颜色和墨迹区分开）+ 一句说明
   「**x 求导得 1，所以 −5x 求导后是 −5。**」
5. 停 3 秒，让评委读完。
6. 学生"改正"：用橡皮擦掉 `−5x`，写 `−5`。
7. 抬笔 → 圈消失，右侧图像自动标出极值点 (−1, 2)、(1, −2) 和它们的切线。

**台词**

> "他写错了。注意 —— 它没有说'这题错了'，它圈的是**这一项**。"（手指点屏幕）
> "然后它把这一项该是什么写在这儿：−5。还有一句为什么 —— x 求导得 1，所以 −5x 求导后是 −5。"
> "改对之后，右边不只是'对了'，是'为什么对了' —— 导数为零的地方，正是图上那两个点。"

**这一段的取舍**：如果圈没出来，**不要重写**，说一句"这里应该圈出来"，点 P1 留下的
「圈整行」按钮继续讲。重写会毁掉节奏。正确项和说明是**本地算出来的**（不调模型、不走网络），
几乎不可能不出；只有 Max 的润色流会超时，而那个是可选的。

**两条彩排要点**

- **`−5x` 一笔写完**。写到 `−5` 就停顿 1.5 秒的话，它已经是 2 项而且**是对的**，会当场判对并画出切线。
- 改错时**先擦后写**，不要划掉（划掉的话那一行里会同时存在两个 `5`）。

## 4. 幕三：动态几何（1:55–2:30）

**手上动作**

1. 换到几何模式，手绘一个三角形 + 从顶点到底边的一条线。
2. 抬笔 → 屏幕把它重建成"可拖动"的图：顶点可拖，中线始终过对边中点，三条中线交于一点。
3. 拖一个顶点给评委看。

**台词**

> "他画的是一个草图，不是精确作图。我们把它变成'有性质'的图 —— 拖它，性质不破。"

**这一段的定位**：锦上添花。**第 30 小时闸门如果不通过就直接砍**，
砍掉不影响前两幕的故事完整性。

---

## 5. 加分幕（2:30–2:45）

二选一，**只演 15 秒**，不要两样都上：

- **矩阵**：写 2×2 乘法，错一个元素 → 圈出那一格，说明写成「第 2 行乘第 2 列：3×6 + 4×8 = 50」这样的算式。
- **积分**：写 `∫2x dx = x²/2` → 圈住答案，说明「x²/2 求导得 x，回不到 2x；原函数应是 x² + C。」

**台词（一句话就够）**

> "同一套引擎，换一个 mode 而已。"

## 6. 出事了怎么说（背下来）

| 现场情况 | 你说的第一句话 | 然后 |
|---|---|---|
| 识别错了 | "识别器偶尔会把 3 看成 8 —— 所以这里允许学生一键改。" | 点 LaTeX 回显改正，继续 |
| 圈没出现 | "这里应该圈出来。" | 点「圈整行」，继续讲这一项错在哪 |
| 说明没刷出来 | "说明在这儿。" | 模板说明是本地算的，一定在；只有 Max 润色会超时，超时就保留模板 |
| 模型超时 | "我们先把刚才真跑的那一次放出来。" | 切回放，**如实说**"这是录制" |
| 网络断了 | "会场网络刚才断了一下，我们有本地回放。" | 切回放 |
| App 崩了 | "这台机器累了。" | 换一台 iPad / 放本地备用视频（**没有第二个平台可切**） |
| 时间被压到 1 分钟 | "只讲一处。" | 直接进幕二 |

**原则：任何异常都不解释超过 8 秒。** 评委记得住的是"它圈对了那一项"，不是你解释得多清楚。

## 7. 备用视频怎么录

- 时长 2 分 40 秒，**一次录完，不剪辑**（剪辑过会被怀疑）。
- 画面：iPad 屏幕录制 + 画中画一只手，声音：现场解说（和脚本同一套话术）。
- 存三处：iPad 本地相册、笔记本本地、云盘各一份（会场断网时前两份够用）。
- 视频开头 3 秒加一行字："现场真机录制，2026-10-2X"。

## 8. 路演材料：三版权重

评分标准开赛前问清。三种配比各准备一套骨架，共 7 页：

| 页 | 技术权重高 | 创意权重高 | 商业权重高 |
|---|---|---|---|
| 1 | 一句话 + 现场演示占位 | 一句话 + 一个学生痛点场景 | 市场规模（K12 数学练习册日均错题量） |
| 2 | 架构图（三端一后端，两条模型分工） | 传统的痛 vs 我们的不同 | 用户画像与付费方 |
| 3 | 为什么对错交给自己的引擎、模型只说人话 | 产品截图：圈住一项 + 正确项 + 一句说明 | 单校试点成本模型 |
| 4 | 逐项比对算法与错误分类 | 现场演示（3 分钟） | 与现有 AI 家教的差异 |
| 5 | 全 Swift：App、引擎、后端一套语言 | 学生视角的一天 | 商业化路径（B2B2C / 教辅合作） |
| 6 | 48 小时的取舍与边界 | 竞争力对比表 | 团队 |
| 7 | 下一步（题库、手写数学 OCR 自研） | 未来形态 | 融资/合作诉求 |

**技术权重版的关键句**：*"我们把'判对错'从模型里拿出来了。模型只做两件事：看懂笔迹、说人话。"*
数字备着：43 个 XCTest、19 条与 Python 参考实现逐条对账、任何垃圾输入都不会崩。

## 9. 答辩 Q&A（20 秒版，背下来）

**Q1：识别不准怎么办？**
"我们把它当输入噪声，不当核心能力。三个保险：固定题目、识别结果用 SwiftMath 回显在笔迹下方可一键改、以及判分完全不依赖识别 —— 判分在我们自己的 Swift 引擎里。"

**Q2：这不就是 prompt 包装吗？**
"不是。对错是程序判定的 —— 逐项比对，连错在哪一项、正确项是什么都是算出来的，模型没参与。
第一版我们连说明都不让模型写，是模板加计算值。你可以理解成：模型没有判分权，也没有解释权。"

**Q3：为什么自己写引擎，不用 SymPy / Mathematica？**
"因为判分要能在 iPad 上离线跑，还要在 1 秒内出结果。SymPy 是 Python，进不了 App；所以我们只做
演示需要的那一小块 —— 多项式求导、逐项比对、中点关系 —— 用 Swift 写死，43 个测试守着，
还和 Python 参考实现逐条对账。"

**Q4：断网还能用吗？**
"能演完。我们把黄金路径的真实返回录下来做回放，断网时切过去。刚才那段如果是回放，我会告诉你。"

**Q5：和 Photomath / Wolfram 有什么不同？**
"它们给整题答案，我们指到**错的那一项**，告诉你这一项该是什么、为什么。
这一代学生的痛点不是'没有答案'，是'不知道错在哪、下次还错'。"

**Q6：48 小时只做了这些？**
"我们只承诺三幕，其中两幕打磨到连续 5 遍不掉链子。多做的每一项都会让主线少打磨一次 —— 这是取舍，不是能力上限。"

**Q7：学生数据/隐私？**
"判分全在设备上，笔记不出设备。只有识别走不通时才把这一行的截图发出去，后端不落盘。"

**Q8：接下来做什么？**
"两件事：把识别从通用视觉模型换成手写数学专用识别；把错因分类做成可累积的数据 —— 错因才是这个产品真正的资产。"

## 11. 手写写法约定（直接决定识别率，练）

| 要点 | 做法 |
|---|---|
| 项间距 | 相邻两项之间留 8 mm，别连笔 |
| 指数 | 写小、抬到右上角，不要和底数连在一起 |
| 减号 | 写清楚，长度 = 数字宽度的 0.6，别写成小横点 |
| 撇号 | `f'(x)` 的撇写短、离 f 近，别写成 `f1(x)` |
| 等号 | 两横清晰，别连成一横 |
| 分数 | 用水平分数线，分子分母各占一半高度 |
| 换行 | 每行只写一个式子，行间距 ≥ 15 mm |
| 改错 | 划掉重写，别涂黑（涂黑会让模型看不清） |
